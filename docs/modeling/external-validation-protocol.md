# 冻结后的外部年度验证协议

协议日期：2026-09-10。本协议用于模型冻结之后取得的独立实际运行资料。当前附件只包含 2025 年，**本仓库没有已完成的 2026 年外部收益结果**。第二轮补充的 2025 年按月滚动实验仍是同年再分析，不能代替本协议要求的证据。

## 1. 冻结对象与证据边界

外部评价沿用题目的物理参数和主结算合约：十分钟区间、单向充放电效率各 0.9、储电边界 1200—10800 kWh、充放电功率各 5000 kW、紧急电按当段电价五倍结算，未交付增购按最终净量结算且可撤回。它验证的是这一模型和交易假设下的策略，不自行外推到新的设备或交易制度。

原主策略参数固定：问题 2、4-2 的风险分位 0.8；问题 3、4-3 的风险分位 0.65，附件 3 光伏权重 0.5。保留贪心反馈参考，并评价本轮固定定义的确定性价格感知反馈；滚动反馈不为日末库存指定额外终端价值。历史预测曲线和残差窗口按已经到达的数据因果更新，但不重新搜索参数、不扩展候选族、不根据外部年度费用选择胜出版本再作为唯一报告。

每次外部评价应记录运行源码、配置、2025 历史数据和输入文件的 SHA-256，连同明确的取得日期、提供方和开发者此前是否接触过该数据的说明。文件中的日期晚于 2025 年，只能证明日历顺序；它不能自动证明数据此前未用于开发。独立性说明缺失或不成立时，应标为“新年度回测，独立性未确认”。若看过评价结果后再修改策略，修改后的结果属于新一轮开发，需要另找尚未使用的数据验证。

## 2. 输入数据契约

使用一个不含 Python 对象的 NumPy NPZ 文件。文件含以下五个数组，电力与价格列均按一天 144 个十分钟右端点排序：

| 键 | 形状 | 单位及含义 |
| --- | --- | --- |
| `dates` | `(N,)` | `YYYY-MM-DD` 日期字符串或不含时刻的 `datetime64`；首日为 `2026-01-01`，严格连续、无重复 |
| `load` | `(N, 144)` | 实際负载代表功率，kW；列 0 对应 00:00—00:10 |
| `pv` | `(N, 144)` | 实際光伏代表功率，kW；与负载具有同一日期和列次序 |
| `dynamic_price` | `(N, 144)` | 波动电价，元/kWh；当段实际价格只在该段执行时可见 |
| `forecast_hourly` | `(N, 4, 24)` | 每日 00、06、12、18 点发布的未来 1—24 小时整点光伏预报，kW |

`N` 为正整数。功率及光伏预报必须有限、非负，电价必须有限且严格为正；不能将缺失数据填成零后冒充观测，也不能把区间电量当作代表功率。固定电价沿用题面给定曲线。小时预报的第一个目标是发布后 1 小时，后续目标可越过午夜；不得把“发布当时”放入未来第 1 小时列。

接口只使用上述五个原始数组；多余键会被忽略并记录名称，不能覆盖固定电价、插值预报或观测锚点。预报插值锚点由程序根据当时已经完成的光伏观测重建。00 点使用前日最后完成区间，06、12、18 点使用该时刻刚完成的区间；不能从输入提供一列未来锚点绕过发布时间检查。未来实测可用于事后结算及产生后续历史残差，不能提前进入本次决策。

数据按 2025 年的相同定义接续。设备、采样口径、预报发布日历或价格可见性发生变化时，必须先说明这种变化；不应把格式能读取等同于数据可比。允许不足一年的连续前缀，报告须写实际起止日期和天数，不能称作完整年度验证。

## 3. 执行与停止规则

外部运行入口为：

```powershell
python scripts/evaluate_round2.py --mode external --future-data path/to/future.npz --output-dir outputs/external-evaluation
python scripts/validate_round2.py --directory outputs/external-evaluation --future-data path/to/future.npz
```

第二条命令独立核对输出，不能把第一条命令执行完毕等同于验证通过。验证器默认按生成记录的输入路径读取未来文件；文件迁移时用 `--future-data` 指定新路径，内容 SHA-256 仍必须与生成记录匹配。`--output-dir` 必须与 `outputs/experiments/round2/` 分开，以保存本轮同年回顾实验。

外部文件接在 2025 年历史之后，预测所需的历史曲线与残差由已到达日期产生。程序分别从 2025 年 1 月 1 日的 6000 kWh 重放贪心与价格感知策略；1 月共用原贪心热启动，2 月起执行各自冻结的反馈，随后把自身 2025 年末真实 SOC 承接至 2026 年。外部评价只汇总未来文件实际提供的日期。两种反馈在外部期初的 SOC 因历史动作可以不同，须如实列出起末库存；这是一贯执行冻结策略的跨年比较，不能声称外部窗口具有相同起点或在年度分界重置库存以获得额外免费电量。

遇到日期缺口、形状不符、非有限值、负数、LP 求解失败或物理约束/费用核验失败时，该次评价应明确失败并保留诊断，不自动删除不利日期或调参后覆盖原运行。缺少预报时，本次接口不静默改用历史光伏；若要研究降级策略，应事先定义并作为另外一条策略保存。

## 4. 输出与报告要求

所有预先定义的策略都报告总费用及其计划、调整、紧急三部分；同时报告紧急电、未利用电、充放电量、起末库存，以及逐日和逐段记录。贪心与价格感知反馈使用相同数据可见性和物理参数；其库存和后续计划可以不同，总费差应作为完整反馈策略的差额说明。

月度差额用于查看收益是否集中于少数季节，同时披露不利月份、最差月份及样本长度。部分年度结果不推断全年，单个新年度结果也不自动证明多年稳定。未实现的置信区间、情景鲁棒性或随机全局最优证明不列为验证结论。

外部数据到来前，本协议能交付的是冻结规则、输入验证和运行入口。只有实际外部输入、不可追溯修改的冻结记录、完整输出及独立性来源说明同时具备后，才可以补写“外部验证已执行”；其是否显示经济改善取决于实际结果。

自动化输入测试和合成未来日期的接口样例只证明加载、历史衔接、因果边界及验算链可以运行。即使这些技术检查全部通过，也不能列作真实外部年度回测，更不能用样例费用声称未来收益。

本次接口样例复制附件中 2025 年最后一天的实际量、电价和小时预报，仅把日期改成 `2026-01-01`，经过完整历史衔接及独立验算，共 727 项检查通过。[接口验证记录](../../outputs/experiments/round2/interface-smoke.json) 明确标注 `is_external_economic_evidence=false`，未收录合成金额。该样例不是新的实际观测，本轮经济结果全部来自已有 2025 年数据。
