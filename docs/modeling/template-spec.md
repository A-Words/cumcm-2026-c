# 附件 5 模板结构与结果文件口径

## 检查对象与输出范围

以题目 PDF 第 3 页附件 5 说明为准，导出五个文件：`result1.xlsx`、`result2.xlsx`、`result3.xlsx`、`result4-2.xlsx`、`result4-3.xlsx`。全部从 `data/raw/附件5` 的原始模板读入，再填充结果，原始附件不改动。工作表名称、顺序、列结构保持不变，不增加辅助计算表。

四个年度文件只保存 2025 年 2 月 1 日至 12 月 31 日的 334 天。1 月的数据可供模型预热与校准，但不增加至模板的年度输出日期范围。数值均为 kWh 或元，功率 kW 必须由模型先转换为每 10 分钟电量，不能直接填入电量列。

所有模板均无合并单元格、无冻结窗格。年度购电表 A2:A335 已存储真正的 Excel 日期，首末日期分别为 2025-02-01 和 2025-12-31。充放电量的每日日块为六行，日期只在日块首行显示，0:00、24:00 储电量分别放在日块前两行的 F 列；最后四行 F 列为空，不把缺省位置填成零。

原储能与紧急表的示例数据使用宋体 10 pt、居中、按日分组的黑色细边框。实际预览发现当前 artifact-tool 的 `copyFrom(all)` 没有把导入格式延伸到原示例区以外，因此导出器对扩展数据区显式沿用上述字体、对齐与日块边框，保留标题和列宽。此处理仅让新增行与原模板示例一致。

## 时间标签错误与修复

原始模板的 144 个购电区间从 `0:10-0:20` 开始，末端为 `23:50-0:00+1`、`0:00-0:10+1`；result1 的最后一段写成 `0:00+1-0:10+1`。这使完整区间相对题目要求的“当天 0:00 至 24:00”整体偏移十分钟，且年度表最后一格文字本身存在跨日歧义。

输出保留 144 个槽及行列位置，修正其标签为 `0:00-0:10`、`0:10-0:20`……`23:50-24:00`。具体修改 result1 的 A2:A145，以及年度计划/调整购电表的 B1:EO1。没有把数组循环平移，也没有把次日首格拼入当天。题面指定的 `10:00-10:10` 始终对应数组索引 60、年度表列 BJ。此修正优先服从题面当天边界、储电状态边界和每日总量定义，并保留原始模板供复核。

所有向量使用 `right-end-0000-to-2400` 约定：第 i 项是 `[i×10,(i+1)×10)` 分钟的电量，若数据采样使用右端点，第 i 项所关联采样时刻为 `(i+1)×10` 分钟。充放电向量按连续 24 格累加得到六个 4 小时段，0:00 和 24:00 状态由 `socStart`、`socEnd` 单独输入。

## 购电量、费用与紧急区间

- “计划购电量”是每日 0:00 制定的 144 段购买量。
- “调整购电量”是其他预报时刻更新后最终执行的购买量，而非相对计划的差值。尚未发生调整的前段等于原计划。
- 两类购电表 EP 列都用 `SUM(B行:EO行)` 计算本表全天量，不包含紧急购电。
- 计划表 EQ 为 `planCost`。调整表 EQ 为 `adjustedCost`，即原计划费加调整增量费，不含紧急购电费。`emergencyCost` 和 `totalCost` 可保留在 JSON 及论文结果中，不能在 Excel 两张表的 EQ 列之间再次相加。
- 紧急购电以连续正电量槽合并成一个区间并求和。日与日之间不合并。阈值 `1e-7 kWh` 仅用于忽略求解器数值残差，合并前后总量必须在数值容差内一致。
- 无紧急购电的日子保留一行日期，时间段填“无紧急购电”，量填真实的 0，以便区分无购电与漏填。每日后续紧急区间的日期留空，遵循题面表 4 的展示方法。
- 数字保存为数值，显示四位小数；日期保存为可排序日期，不字符串化。原始标题和版式沿用，时间错误除外。

## 模型到导出器的 JSON 协议

输入路径为 `outputs/main/results.json`。所有 144 元素向量均为有限非负数值，日期必须按顺序连续覆盖 334 天。

```json
{
  "schemaVersion": 1,
  "slotConvention": "right-end-0000-to-2400",
  "q1": {
    "plan": ["144 个 kWh 数值"],
    "charge": ["144 个充电 kWh 数值"],
    "discharge": ["144 个放电 kWh 数值"],
    "socStart": 6000,
    "socEnd": 6000
  },
  "q2": {"days": ["按下述 day 结构排列的 334 天"]},
  "q3": {"days": ["同 day，另含 adjusted 和 adjustedCost"]},
  "q4_2": {"days": ["同 q2"]},
  "q4_3": {"days": ["同 q3"]}
}
```

上面的字符串仅用于说明长度，真实 JSON 中必须是数值数组。每日结构如下：

```text
date: YYYY-MM-DD
plan: number[144]
planCost: number
charge: number[144]
discharge: number[144]
socStart: number
socEnd: number
emergency: number[144]
adjusted: number[144]       // 仅 q3、q4_3 必须
adjustedCost: number        // 仅 q3、q4_3 必须
emergencyCost: number       // 可选，导出器不写入模板额外位置
totalCost: number           // 可选，导出器不写入模板额外位置
```

## 构建与复核

`scripts/export_results.mjs --inspect` 只读导入五份模板并将原模板预览保存至 `tmp/workbook-previews`。默认执行读取 JSON 并导出五个正式文件至 `outputs`。需要只更新部分结果时，可使用 `--files=result3.xlsx,result4-3.xlsx`；此参数也限制模板检查及保存后预览的文件范围，但保存后的自动核验和 `--verify` 始终覆盖全部五份文件。`--preview-saved` 重新打开年度结果并渲染总量/费用列、调整表 6:00 附近、年底购电行和储能/紧急表尾，补充检查后期扩展行。导出使用 Codex bundled Node 与 `@oai/artifact-tool`，不使用 openpyxl/pandas/xlsxwriter 写 Excel。

首次实际 Excel 填充前运行一次技能提供的 `mark_artifact_operation_started.mjs --operation-kind edit --expected-output-count 5 --output-format xlsx`。脚本本身不重复调用该标记。导出器检查日期、维度、有限值、逐日总量公式、费用对应关系、紧急区间合并总量，重算后扫描公式错误并渲染每个工作表的首段。保存后另用只读方式检查行列、模板头、日期和关键数值，避免只凭导出成功判断正确。

评审后的定向更新仍在同一会话内，沿用已执行的一次标记。问题 3、4-3 的模板填入修订主策略、`final_net` 合约的结果；逐笔合约的重优化及冻结重计费分别保存在修订实验 JSON 和论文，不混入主结果表。核验报告另记录各购电表的全年电量、费用合计和 12 月 31 日末行数值，并核对“最终交付费用加 JSON 紧急费用”等于全年总费用。
